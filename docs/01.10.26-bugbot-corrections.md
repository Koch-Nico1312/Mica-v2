# Bugfix review, 1 October 2026

The independent reviewer examined the current branch and working-tree changes.
Findings were corrected centrally, covered with regressions, and submitted to
the same independent reviewer again. The installed `review-bugbot` workflow was
used with a read-only review agent; a dedicated Bugloader tool is unavailable.

## Confirmed findings corrected

1. Move undo could delete the only surviving file before restoring its source.
   Undo now restores originals atomically before deleting destinations and refuses
   a missing original parent. Write and replace failures retain the surviving data.
2. Live restore could attach stale removed steps to a preserved newer plan.
   Existing plans retain their complete parent/child revision together.
3. Another host file action could edit a file between undo checks and compensation.
   File execution and undo share a process-wide filesystem lease and recheck state
   immediately before atomic replacement.
4. Voice capture could retain a conversation after its privacy setting changed.
   Finalization applies the current no-storage setting; desktop privacy changes
   cancel active capture, and an initially private capture remains private.
5. Concurrent audit/presence writes could invalidate recovery archives.
   Audit snapshots freeze a validated chain under a cross-process lock, presence
   respects maintenance, and recovery archives are verified before replacement.
6. File-controller errors could be recorded as successful actions.
   Known failure responses raise a typed failure and retain uncertain receipts.
7. Host receipt connections leaked SQLite handles on Windows.
   Connections close explicitly after each read or transaction.
8. Emergency stop could be cleared during live restore.
   Clearing now requires a storage lease and refuses incomplete-restore markers;
   stop activation remains available during maintenance.
9. Stable execution keys with omitted task IDs were rejected on retry.
   These requests derive a stable task ID and return the cached result; conflicting
   explicit IDs remain rejected.
10. Implicit file paths disagreed between receipts, execution, and allowlists.
    Shared path resolution follows actual Desktop defaults and operation aliases,
    rejects unsafe link paths, and checks the actual affected paths.
11. Preview/correction could count a long pause against execution time.
    A durable pause timestamp survives previews, corrections, and restore while
    preserving consumed time, tool calls, and correction counters.
12. Correcting an unresolved action could assign it a new key and repeat its effect.
    Durable dispatch timestamps and the dispatcher lease prevent correction until
    the outcome is reconciled; failed/running identities and claims remain intact.
13. Resuming a failed plan could execute a dependent later step.
    Activation rejects unresolved outcomes, and dispatch requires all preceding
    steps to be completed. Reconciliation permits subsequent safe continuation.
14. Old backups could lose uncertainty for already blocked or retried steps.
    Import now backfills dispatch evidence after rebuilding the complete logical
    state, in both verification and live restore. Legacy pending steps with
    unknown prior attempts remain blocked until reconciliation.
15. Legacy database upgrades could mark uncertain pending steps without blocking
    execution. Constructor migration now performs the same pending-to-blocked
    transition as backup import.

Related hardening makes schema migrations transactional so multiple workers cannot
race to add the same column. Old journals and restored running steps preserve
uncertainty when upgrading to durable dispatch timestamps.

## Validation scope

Regressions exercise failed atomic undo, concurrent host runners, recovery audit
snapshots, restored plan revisions, emergency-stop maintenance, stable retries,
privacy finalization, pause budgets, duplicate-effect prevention, in-flight
correction refusal, and reconciliation of dependent steps.

The ordinary test suite is `tests/`. The separate
`backend/tests/test_chonkie_runtime.py` is a fresh-container dependency acceptance
test and requires the backend image's locked Chonkie dependencies. Repository-wide
discovery in the desktop virtual environment could not collect that test because
Chonkie is not installed there. Docker, live models, and physical audio acceptance
are outside this local validation.

The seventh independent review round reported no further actionable findings.
The latest complete `tests/` run passed 508 tests and 70 subtests. The final
constructor-migration change and its subsequently added test passed four focused
legacy regressions; independent final verification passed 12 selected tests.
Git whitespace checks passed. Two dependency deprecation warnings remain.

All changes are saved locally and remain uncommitted. At the user's separately
authorized 10-percent remaining usage threshold, a desktop shutdown note was
written and `shutdown /s /t 60` was invoked.

## Follow-up review, 2 October 2026

A second review round covered the API composition split, the `mica_shared`
extraction and the later hardening. Two defects were corrected:

1. The route-enumeration authentication test could never fail. FastAPI 0.141
   represents included routers as `_IncludedRouter` wrappers, so
   `isinstance(route, APIRoute)` matched zero routes. The test now enumerates
   the generated OpenAPI operations (111 HTTP operations; no schema-hidden
   routes), asserts a coverage floor and exercises every non-exempt operation
   anonymously against the token gate.
2. `POST /v1/vision/analyze` accepted an unbounded base64 image and decoded it
   before the vision engine's 5 MB limit applied. The request schema now bounds
   the field to the engine's canonical base64 size (6,990,508 characters), so
   oversized payloads fail with 422 before any decode.

Re-verified with the complete suite (517 tests and 77 subtests), Ruff and
`git diff --check`; route parity against the former monolith holds (all former
endpoints are still registered, twelve were added).
